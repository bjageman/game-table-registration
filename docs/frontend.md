# Frontend

Run `npm ci` and `npm run dev` from `frontend/`, then open http://localhost:5180. The moderator UI restores Discord sessions, starts OAuth login, and supports logout. Authentication uses server-owned cookies; the CSRF token stays in memory. The root `index.html` is a static preview; use `frontend/` for ongoing development.

For headless access, set `DEV_HOST=0.0.0.0` and `PUBLIC_URL=http://your-host:5180` in the root `.env`. The configured hostname is allowlisted. API proxying targets loopback port 8000. Register your PUBLIC_URL plus `/api/auth/callback` as the redirect URI in Discord's OAuth2 settings. Use the exact same origin in your browser.

Checks: `npm run lint`, `npm run build`, `npm test`, and `npx playwright install chromium && npm run test:e2e`. Stop any existing server on port 5180 before the browser tests. CI also builds the frontend Docker image. Browser tests mock the API and check login/logout on desktop and mobile without contacting Discord.

Run `docker compose -f compose.yml -f compose.frontend.yml up --build -d --wait` from the repository root. Open http://localhost:8080. Set PUBLIC_URL to your browser origin. The frontend Compose file extends the backend Compose file and is not a standalone deployment.

The event list loads the server's event records with start times, signup duration, table capacities, and publication status. Times use the browser's local timezone. Refresh retrieves the latest server state. A lost session or removed moderator access hides the dashboard. Events awaiting publication review show a check-Discord notice.

Create event opens a draft form for the title, local event date/time, whole-hour signup duration (1–768), and 1–10 tables with capacities (1–999, default 15). MUI X uses a combined date/time picker on desktop and separate date and time pickers on mobile, defaulting to the current time rounded up to the next 15-minute interval. The browser sends a timezone-qualified timestamp. Table names must be distinct, and the event must start after the signup window ends. Saving creates a draft; it does not publish a Discord message. Failed requests keep entered values for correction.

Drafts offer Publish to Discord with a confirmation dialog naming the event, tables, capacities, and signup duration. Confirmation sends one CSRF-protected publication request; the open event links to its Discord poll. A network error, server failure, or conflicting publication hides further publish controls until the list is refreshed from the server. Check Discord before retrying uncertain publication. Events already publishing or held for review never offer automatic retries.

Validation errors are associated with their fields, including errors returned by FastAPI. Local times that are missing or occur twice during daylight-saving transitions are rejected rather than silently shifted. Requests time out after 15 seconds; mutations are never automatically retried. Tests cover the complete mocked login/create/publish/logout journey, role/session loss, server validation, stalled/uncertain publication, and daylight-saving transitions on desktop and mobile.

For a manual acceptance check in a dedicated Discord test server: configure the OAuth callback for the exact PUBLIC_URL, log in as an allowed moderator, save a future draft, verify that no poll exists yet, then explicitly confirm publication and follow the Discord poll link. Refresh and confirm that the open event offers no publish action, then log out. This check sends a real poll only when you confirm publication.

Unpublished drafts offer Edit draft and Delete draft. Editing reuses the event form with the saved values; deleting requires confirmation. Both mutations require moderator access and CSRF protection and atomically require draft status, preventing changes after publication begins. Publication reloads the claimed event before constructing its poll payload so a prior committed edit is included.

The event modal retrieves current Discord poll voters per table and refreshes every 15 seconds after each completed request while open. Removing a vote removes that player on the next refresh. Counts show current signups relative to capacity; a multi-select voter appears under every selected table. These are signup preferences, not seat assignments or waitlist positions. Drafts show zero players. Lookup failures preserve the last loaded list and display an error; they are never shown as an empty result.

Open signups can be deleted from the modal header. The shared confirmation offers an unchecked Also delete the poll on Discord option. Leaving it unchecked removes only the TableSignup record. Selecting it deletes the Discord poll message before committing the local deletion; a failure retains the signup for retry. Player names open a nested Player Information modal with a static Discord name, editable real name, and read-only current weighting (default 1.0; assignment weighting remains a placeholder). Profiles are keyed by guild and Discord user ID and are stored independently of event/poll records, so event deletion does not erase saved information. Profile saves require moderator authorization and CSRF protection.

The profile dropdown links to Settings (`/#/settings`). Users choose a manageable Discord server, open Discord's official Add TableSignup to Discord flow, then refresh the channel list and save an eligible text channel. Refresh Server List reauthorizes the additional `guilds` scope and returns to Settings, which is useful for sessions created before server discovery was introduced. The selection persists per account, and new accounts are guided through setup before seeing events. Changing servers/channels changes the displayed event list without moving or republishing old polls. Existing app moderators keep access to the legacy default destination.

Open signup modals offer Close Signups. The shared centered Cancel/Confirm dialog ends the native Discord poll and continues only after Discord finalizes its results. Closing responses are continued briefly while the dialog is open; failed network requests are not automatically repeated. A pending/interrupted closing can be finished with the same button later. Assigned events display the saved players and eligible waitlists, with no further live voter refresh. Signup opening time is preserved when signups close early. Assignment weights use the stored profile values; the weighting editor remains read-only for now.

Allowlisted accounts see Populate Test Users on draft and open event modals. Confirming adds persistent test players for the normal publish and close flow. Test events and announcements are marked TEST. After closure, the modal shows announcement delivery status; Retry Announcement uses saved placements. Discord links use the original HTTPS destination so the browser and operating system can handle opening Discord.

Player Information includes Guaranteed Seat, which guarantees placement at one of the tables the player selected. These server-wide settings apply when future signups close, including for saved test users. Players still need to sign up. Test users additionally expose editable weights from 0.1–10.

Modal inputs use shared FormField defaults inside FormFields, which owns vertical spacing and floating-label clearance. Keep helper text with its field rather than adding individual margins.

Display Name overrides Discord names in app signup, assignment, and waitlist entries when set. Saving refreshes the list immediately; clearing restores the Discord name. Discord posts and saved lottery data retain Discord identities. Existing profile names are preserved.

Assigned event modals offer an Archive icon with shared Cancel/Confirm controls. Archived events are hidden from the default list; Show Archived includes them again with saved placements and waitlists.
